# wealth-nav-watch

**中国银行代销理财净值的每日增量数据。**

每天自动抓一次中行的净值披露页，只把**新增**的净值存成 CSV 推进仓库：
`data/YYYY-MM-DD.csv`，文件名是运行日期（北京时间）。

```
data/
  2026-11-11.csv     ← 当天新增的净值
  2026-11-12.csv
  ...
```

没有新增数据的那天**不产生文件**（不会出现只有表头的空 CSV）。

---

## 数据从哪来

中国银行「当日代销理财产品净值」静态页：

```
https://www.boc.cn/sourcedb/<目录>/index_<页码>.html
```

纯静态 HTML，**不用登录、不用签名、不用 JS 渲染**。

| `source_dir` | 是什么 | 页数（实测 2026-11） | 行数 |
| --- | --- | --- | --- |
| `srfd6_2024` | 代销**理财** | 196 | 9,798 |
| `srfd2_2024` | 代销**基金** | 121 | 6,031 |
| `srfd3_2024` | 代销**资管** | 199 | 9,949 |

三个源表头完全一致（8 列），格式统一。

---

## 为什么必须自己攒

**中行这个归档站每只产品只保留最新的一条记录。**

实测（2026-11-11，全站 196 页）：

- 9,798 行 / 9,363 个产品代码；
- 拥有 **≥2 个不同净值日期**的产品 = **0 只**；
- 最后披露日期跨 2019-05 ~ 2026-11，共 1,183 种。

也就是说：**历史批次一旦被新披露覆盖就永久消失**，页面本身查不到历史。
想攒净值序列，**只能每天存一条**。

这也意味着：**本仓库的数据是从第一次运行那天开始攒的**，之前的历史谁也补不回来。

---

## 增量是怎么判的

去重键 = `(source_dir, code, nav_date)`，**不含** `run_date`。

- 今天新披露的产品 → 新组合 → 进今天的文件；
- 昨天披露过、今天净值没变的 → 组合没变 → 不重复记；
- 中途停跑几天 → 那几天的批次重新出现时会被自动补上（前提是还没被新披露覆盖）。

因为中行是**按估值日披露**的，同一批数据会在页面上停留好几天 ——
所以「今天抓到的」不等于「今天披露的」。真正的披露批次看 `nav_date`。

## 字段

| 字段 | 含义 | 口径 |
| --- | --- | --- |
| `code` | 产品代码 | 中行的**销售代码**（份额代码），不是登记编码 |
| `product_name` | 产品名称 | 原样保留；上游有少量产品名称是空的 |
| `nav_date` | **净值日期** | 中行页面的「截止日期」= **估值日**（不是发布日） |
| `unit_nav` | 单位净值 | 原始字符串，空 = 这一项没有 |
| `cum_nav` | **累计净值** | 含分红再投，**算收益用这个** |
| `period_change_pct` | 期间涨跌幅（%） | 中行第 7 列。表头写的是「日净值增长率」，**实际是相对上一披露日的涨跌幅**，且是**单位净值口径** |
| `per10k` | 每万份基金单位收益（元） | 货币基金口径 |
| `yield7d_pct` | 七日年收益率（%） | 货币基金口径 |
| `source_dir` | 来源静态页 | `srfd6_2024` / `srfd2_2024` / `srfd3_2024` |
| `run_date` | 本次抓取日期 | 北京时间，等于文件名 |

数值**保留页面上的原始字符串**，不做浮点转换 ——
一是避免精度损失，二是能区分「空」（这项没有）和 `0`（真的就是 0）。

### 两个容易踩的口径

1. **算收益用 `cum_nav`，不是 `unit_nav`。**
   分红型产品两者能差 0.14 倍，拿单位净值算收益会算错，**甚至方向相反**
   （实测同一条记录：用单位净值算三个月是 -0.42%，用累计净值算是 +0.05%）。

2. **`nav_date` 是估值日，不是发布日。**
   一只周五估值的产品，净值会在下周一才出现在这一页上。
   想知道「今天能拿到的最新净值是哪天的」，看 `nav_date` 而不是 `run_date`。

## 怎么用

### 当数据看

直接读 `data/` 下的 CSV。想只要理财：

```bash
awk -F, 'NR==1 || $9=="srfd6_2024"' data/2026-11-11.csv
```

### 本地跑一次抓取

需要 Node 18+（零第三方依赖，只用自带的 `fetch`）：

```bash
node scripts/fetch-boc-nav.mjs                # 抓全部源，算增量，写 data/<今天>.csv
node scripts/fetch-boc-nav.mjs --dry-run      # 只算不写，看看这次会新增什么
node scripts/fetch-boc-nav.mjs --dir srfd6_2024 --pages 20   # 只抓理财的前 20 页
```

参数：

| 参数 | 说明 |
| --- | --- |
| `--dir a,b` | 只抓指定来源（默认三个全抓） |
| `--pages N` | 每个源最多翻几页（默认 220，实际最后一页之后是空页） |
| `--dry-run` | 只算不写 |
| `--date YYYY-MM-DD` | 指定运行日期（默认北京今天） |

### 手动补跑

Actions → **中行净值每日增量** → Run workflow。

## 限制

- **补不了合并之前的历史** —— 中行页面上没有就永远没有。
- **被新披露覆盖的批次补不回来** —— 页面只留最新一条。
- **产品名偶有为空** —— 上游就是这样，脚本原样保留，不编造。
- **数据来自中行的展示口径**，与基金业协会的登记口径不一定一致；用于投资判断请以产品说明书和官方披露为准。

## 许可

数据来自中国银行公开披露页面。本仓库只做数据留存与分析，不改变原值的含义。
